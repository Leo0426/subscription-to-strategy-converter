# Subflow 6.5

镜像：`subflow:6.5-amd64`，平台：`linux/amd64`，应用版本：`6.5.0`。

## 发布内容

本版本优化 Surge iOS 策略发布，减少无效测速并补充只读安全审计，同时保持机场连接配置的所有权边界。

- Profile 可显式选择 Surge 自动测速组使用全部兼容节点或仅 AnyTLS；手动选择仍保留全部兼容节点。
- 自动组使用 100 ms 容差；过滤空组会完成父级引用闭包，不会补造 `DIRECT`。
- 当前 Surge 目标按 iOS 能力编译，Mac 专属 `PROCESS-NAME` 规则会跳过并报告类型与条数。
- 原生 Surge `[General]`、`[Host]`、`[Proxy]` 和辅助段保持原样；局域网无认证、旧式 DoH 名称、`info` 日志、完整隧道范围和关闭证书验证只生成脱敏提示。
- `skip-cert-verify` 不会自动关闭；AI 故障切换仍要求两个明确节点，通用探针不代表服务接受该出口。
- 工作台保存并恢复 Surge 偏好，包括 API 创建的未来协议列表，不会因无关编辑静默改写。

## 兼容性与风险

6.5 沿用 6.2 的数据库结构，无需迁移。没有 `surge_preferences` 的旧 Profile 保持原自动组成员。Surge 规则能力现在以 iOS 为准，因此原来被输出但在 iOS 上无效的 `PROCESS-NAME` 会消失，并通过 warning 显式说明。

安全审计不修改机场配置。若机场要求 `skip-cert-verify=true`，配置会继续保留；只有机场提供有效证书后才应人工关闭。实际 NR 连通性、Surge iOS 导入、ChatGPT / Claude 登录与对话仍需在真实设备和网络中确认。

## 升级与回退

升级前停止旧容器并备份原数据目录及存在的 WAL/SHM 文件，沿用原端口、环境变量、数据挂载和访问地址，以保留 Profile ID、token 和订阅链接。

```sh
sha256sum -c subflow-6.5-linux-amd64.tar.gz.sha256
docker load -i subflow-6.5-linux-amd64.tar.gz
```

macOS 可使用 `shasum -a 256 -c subflow-6.5-linux-amd64.tar.gz.sha256`。

新部署示例：

```sh
docker run -d --name subflow-6-5 \
  --restart unless-stopped --platform linux/amd64 \
  -p 8000:8000 -v subflow-data:/app/data \
  subflow:6.5-amd64
```

回退时停止 6.5 容器，恢复升级前数据库备份，并使用原镜像和原部署参数启动。

## 部署后验证

1. 确认容器 healthy，`/health` 成功、`/openapi.json` 显示 `6.5.0`、页面显示 `6.5`。
2. 打开旧 Profile，确认没有 Surge 偏好时自动组仍包含全部兼容节点。
3. 选择“仅 AnyTLS”，确认 Surge 自动组缩小、手动组不变，兼容 warning 不含订阅凭据。
4. 强制刷新已保存订阅，让手机重新拉取，并在 Surge iOS 检查 `FINAL`、策略组和实际节点连接。
5. 用同一节点验证 ChatGPT / Claude 主站、登录和资源请求；通用测速成功不等于服务可用。
