# Subflow 6.6.1

本次补丁修复订阅发布、策略预览和来源审计中的边界问题。当前交付范围是源码提交；Docker 镜像、归档和运行环境部署需另行构建与验收。

## 用户可见变化

- 已保存 Profile 的订阅刷新会分别处理各客户端产物。来源暂时不可用时，只回退到同一保存代次、同一客户端的上次成功产物，并标记 `X-Subflow-Stale: true`；它可能仍由旧版编译器生成。无效来源或配置错误会明确报错。
- Surge 和 Shadowrocket 原生订阅保留来源的非分流设置，替换路由规则时处理带 BOM、注释及原有规则段的输入。检查失败会显示具体错误，避免发布错误的配置。
- 工作台的服务出口检查、旧策略升级预览和规则顺序提示更完整；编辑已有 Profile 时继续沿用原 ID、token 和订阅链接。
- PolicyWorkspace 的规则预览与重新编译会保留规则选项及复杂表达式，并正确处理 `MATCH` / `FINAL`、RuleProvider 引用和修改后的目标。
- 规则来源审计补全输入结构与格式校验；CLI 诊断失败会返回失败状态，便于自动化发现问题。
- 网络读取、兼容转换和临时会话对无效输入、超时、响应大小与内存占用设置明确边界。

## 兼容性与风险

无需手动数据库迁移或更换现有 Profile 链接。保留原数据挂载、端口和环境变量；升级后让客户端强制刷新订阅。历史 PolicySnapshot 的升级仍由工作台预览后显式应用。

本次测试验证了接口、解析、发布及工作台行为。真实客户端导入、节点可用性，以及 ChatGPT / Claude 登录与对话仍需在实际网络和设备上验收。临时 `/session` 链接存于进程内、最长保留 24 小时；单进程最多保留 64 条，每条不超过 1 MiB，达到容量时会逐出最早创建的会话。过期、逐出或服务重启后的会话链接返回 410，超限提交返回 413；长期订阅请使用 Profile 链接。

## 升级与回退

部署前备份数据目录及 SQLite WAL/SHM 文件。使用本次源码构建并启动 6.6.1，保持原数据挂载和访问地址。若需指定架构镜像及归档：

```sh
./scripts/docker-build.sh amd64 6.6.1
./scripts/docker-export.sh amd64 6.6.1
```

这会在本地生成 `subflow:6.6.1-amd64` 和 `dist/docker/subflow-6.6.1-linux-amd64.tar.gz`；当前源码提交本身不包含这些产物。回退时停止 6.6.1，恢复升级前数据备份，再用先前可用的 6.6.0 镜像和相同部署参数启动。

## 部署后验收

1. 检查 `/health`、`/openapi.json` 的版本 `6.6.1`，以及页面版本标记。
2. 对代表性的 Clash、Surge、Shadowrocket Profile 强制刷新，确认配置可导入且各客户端取得对应产物。
3. 编辑并保存已有 Profile，确认链接保持不变；分别检查无效来源报错与暂时不可用来源的同目标回退行为。
4. 在实际设备上验证关键服务流量和登录路径，确认所选节点满足使用需求。
