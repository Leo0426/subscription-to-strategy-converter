# Subflow 6.6

镜像：`subflow:6.6-amd64`，平台：`linux/amd64`，应用版本：`6.6.0`。

## 发布内容

本版本补齐手机端 ChatGPT 登录出口一致性和 Surge iOS 国内字节系应用分流，同时保持未知流量的代理兜底。

- `AI 服务` 增加手动的新加坡节点池，并继续提供美国节点池和全局手动选择；通用测速不会自动跨地区切换 AI 出口。
- `accounts.google.com`、`oauth2.googleapis.com`、`openidconnect.googleapis.com` 三个 Google OpenID Connect 主机与 ChatGPT 会话统一走 `AI 服务`，普通 Google 流量仍使用 Google 策略。
- 补充抖音、红果和番茄小说的国内 `.com` 域名及专属 CDN 直连规则，覆盖 `douyin.com`、`snssdk.com`、`fqnovel.com`、`fanqienovel.com` 等实际流量。
- 国内字节系规则位于 TikTok/海外服务之后，不包含上游的 `USER-AGENT,TikTok*` 或 TikTok 进程项；`FINAL` 仍为 `默认代理`，没有导入完整 China 规则集。
- RuleProvider 仍为 8 个固定版本来源，没有增加冷启动远程下载；公开审计快照已随模板更新。

## 兼容性与风险

6.6 沿用 6.5 的数据库结构，无需迁移。已有 Profile 的 URL、token 和保存的 Surge 偏好保持不变；部署后需要强制刷新客户端订阅，旧的替换式 PolicySnapshot 仍需在工作台显式升级。

本次只保证生成规则和编译路径。真实节点是否被 ChatGPT 接受、Google 登录与会话是否保持同一可用出口、Surge iOS 导入以及手机网络表现仍需在实际设备验证。未被域名规则覆盖的国内 `.com` 流量仍可能落入 `FINAL,默认代理`。

## 升级与回退

升级前停止旧容器并备份数据目录及存在的 WAL/SHM 文件，沿用原端口、环境变量、数据挂载和访问地址。

```sh
sha256sum -c subflow-6.6-linux-amd64.tar.gz.sha256
docker load -i subflow-6.6-linux-amd64.tar.gz
```

macOS 可使用 `shasum -a 256 -c subflow-6.6-linux-amd64.tar.gz.sha256`。

新部署示例：

```sh
docker run -d --name subflow-6-6 \
  --restart unless-stopped --platform linux/amd64 \
  -p 8000:8000 -v subflow-data:/app/data \
  subflow:6.6-amd64
```

回退时停止 6.6 容器，恢复升级前数据库备份，并使用原 6.5 镜像和部署参数启动。

## 部署后验证

1. 确认容器 healthy，`/health` 成功、`/openapi.json` 显示 `6.6.0`、页面显示 `6.6`。
2. 强制刷新已保存订阅，确认 `AI 服务` 包含美国节点、新加坡节点和手动选择，且地区组保持手动选择。
3. 在 Surge iOS 请求记录中确认 Google 登录主机与 ChatGPT 会话使用同一个 `AI 服务` 出口。
4. 打开抖音、红果和番茄小说，确认相关 `.com` 域名命中 `DIRECT`；同时确认 TikTok 没有被 UA 或进程规则强制直连。
5. 用实际节点验证 ChatGPT / Claude 登录、对话和资源请求；通用测速成功不代表服务接受该出口。
