# Subflow 6.7

镜像：`subflow:6.7-amd64`，平台：`linux/amd64`，应用版本：`6.7.0`。

## 发布内容

本版本补齐 Surge iOS 对国内 `.com` 域名的直连兜底。先前 iOS 产物跳过 `GEOSITE,cn,DIRECT`，而 `GEOIP,cn,DIRECT,no-resolve` 不主动解析未解析的域名，部分国内应用请求因此落入 `FINAL,默认代理`。

- Leo 增加固定版本的 China RuleProvider，排在具名服务规则之后、最终代理规则之前；Mihomo 使用 classical 列表。
- Surge iOS 将该来源映射到同一提交的纯域名 `DOMAIN-SET`，避免完整 Surge 列表中的宽泛 `USER-AGENT` 条目抢占服务分流。
- `FINAL` 继续使用 `默认代理`；未命中国内列表的其他流量仍按原有规则处理。
- 公开规则源审计已更新：9 个来源均有效，结构评分 99.96/100，冷启动下载总量为 230,392 B。此处修订了 [ADR 0015](../adr/0015-ai-session-routing-and-inline-budget.md) 的 8 来源限制，原因记录在 [ADR 0017](../adr/0017-surge-ios-domestic-domain-fallback.md)。

## 兼容性与风险

6.7 沿用 6.6 的数据库结构，无需迁移；现有 Profile URL、token 和 Surge 偏好不变。新增外部规则源需要客户端成功下载，且规则集无法覆盖所有国内域名。Mihomo 也会加载新增的 China classical 规则，可能改变此前未被 `GEOSITE,cn` 覆盖的域名分流；具名服务规则仍优先。

自动化验收仅证明产物生成、版本和接口行为。Surge iOS 实机导入、实际请求命中与国内应用功能仍须在设备上核对。

## 升级与回退

升级前停止旧容器，备份数据目录及存在的 WAL/SHM 文件，并保留原端口、环境变量、数据挂载和访问地址。验证并导入归档：

```sh
shasum -a 256 -c subflow-6.7-linux-amd64.tar.gz.sha256
docker load -i subflow-6.7-linux-amd64.tar.gz
```

新部署示例：

```sh
docker run -d --name subflow-6-7 \
  --restart unless-stopped --platform linux/amd64 \
  -p 8000:8000 -v subflow-data:/app/data \
  subflow:6.7-amd64
```

回退时停止 6.7 容器，恢复升级前的数据库备份，并按原参数启动已保留的 6.6 镜像。旧版本不会包含新的国内域名兜底。

## 部署后验证

1. 确认容器为 healthy，`/health` 成功、`/openapi.json` 显示 `6.7.0`、页面显示 `6.7`。
2. 强制刷新 Surge iOS 订阅，确认新规则包含固定版本的 `China_Domain.list,DIRECT`，位于具名服务之后和 `FINAL,默认代理` 之前。
3. 在 Surge iOS「最近请求」里检查此前误代理的国内域名实际命中 `DIRECT`；若仍走代理，记录域名、命中规则和策略。
4. 抽查 ChatGPT、Google 登录、Apple、Microsoft 和 TikTok 等具名服务继续使用预期出口。
